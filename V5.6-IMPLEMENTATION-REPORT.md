# IntelliHire V5.6 — Implementation Report: Unified Candidate Intelligence Dashboard

## 1. Objective

IntelliHire V5.6 delivers a **Unified Candidate Intelligence Dashboard** that aggregates all candidate domain signals (Identity, Active Resume, NLP Skill Extraction, Coding Profiles, Academic Profile, Project Portfolio, Certificates, Application History, and AI Evaluation) into a single, cohesive recruiter-facing experience.

The system empowers recruiters to quickly answer:
1. **WHO** is this candidate?
2. **WHAT** can they do?
3. **WHAT** evidence supports those skills?
4. **HOW** well do they match this specific job?
5. **WHAT** are their strengths and skill gaps?
6. **SHOULD** the recruiter shortlist, interview, hire, or reject them?

## 5. Unified AI Scoring & Consolidation Architecture

### 5.1 Single Source of Truth
The system maintains **ONE source of truth** for candidate scores calculated exclusively in `candidateIntelligenceService.js`:

1. **ATS Score (0–100)**: From candidate's active resume `atsScore`.
2. **Semantic Match (0–100)**: From FastAPI `/job-match` (SBERT / TF-IDF similarity) or deterministic skill overlap fallback when evaluating against a job.
3. **Academic Score (0–100)**: Derived deterministically from CGPA and backlogs: `clamp((cgpa / 10) * 100 - backlogs * 8)`.
4. **Coding Score (0–100)**: Derived from LeetCode solved count, GitHub contributions/repos, and HackerRank achievements.
5. **Project Score (0–100)**: Derived from project count, tech breadth, verified GitHub URLs, live deployment demos, and embedded portfolio scores.
6. **Certificate Score (0–100)**: Derived from certificate count and verified credential URLs/IDs.
7. **Final AI Composite Score (0–100)**:
   - *With Job*: Weighted composite: `(Semantic * 0.35) + (ATS * 0.20) + (Coding * 0.15) + (Projects * 0.15) + (Academic * 0.10) + (Certificates * 0.05)`
   - *Without Job*: Employability composite: `(ATS * 0.25) + (Projects * 0.25) + (Coding * 0.20) + (Academic * 0.15) + (Certificates * 0.15)`
8. **AI-Assisted Recommendation Tier**:
   - `90 – 100`: **Strongly Recommended**
   - `80 – 89`: **Recommended**
   - `70 – 79`: **Consider**
   - `60 – 69`: **Needs Review**
   - `< 60`: **Low Match**

## 6. Security & Access Control

- **Recruiters**: Can view any candidate's unified intelligence profile and take status actions (`Shortlisted`, `Interview`, `Selected`, `Hired`, `Rejected`).
- **Candidates**: Can view only their own intelligence profile (`/api/candidates/me/intelligence` or when `req.user.id === req.params.candidateId`). Requests to access other candidates return `403 Forbidden`.
- **Private Notes**: Recruiter notes in `Application.recruiterNotes` are protected and not leaked in candidate views.

---

## 7. Performance & Resilience

1. **Zero N+1 Queries**: All candidate domains are fetched in parallel with a single `Promise.all` round-trip.
2. **AI Failure Resilience**: If the FastAPI AI Engine is offline or times out, the backend gracefully falls back to deterministic skill matching, ensuring candidate profiles always render.
3. **Missing Module Resilience**: Candidates with incomplete profiles (e.g. no coding profile or projects) do not throw errors; empty states are rendered cleanly with zero `NaN` or `undefined` values.
4. **Skeleton Loading**: Frontend uses structured pulsing skeleton loaders preventing blank screens during data fetching.
