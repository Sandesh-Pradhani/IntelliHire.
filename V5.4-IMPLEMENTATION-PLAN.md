# IntelliHire V5.4 Certificate Management Implementation Plan

## Current Architecture
- Frontend: React/Vite in `client`, route modules in `client/src/routes`, shared layouts/components under `client/src/components`, HTTP access through `client/src/services/http.service.js`.
- Backend: Express in `server`, Mongoose models in `server/models`, auth and role middleware in `server/middleware`, feature routes mounted from `server/server.js`.
- AI engine: FastAPI in `ai-engine/app/main.py`, routers in `ai-engine/app/routers`, scoring services in `ai-engine/services`, Pydantic schemas in `ai-engine/schemas`.
- Candidate profile: portfolio features already include projects, certificates, coding profiles, experience, languages, links, academic profile, and resume history.
- Existing certificate support: `server/models/Certificate.js` and inline certificate CRUD in `server/routes/portfolioRoutes.js` exist, but are basic and not V5.4-complete.

## Reusable Components Discovered
- Auth: `server/middleware/authMiddleware.js`.
- Authorization: `server/middleware/roleMiddleware.js`.
- Uploads: `server/middleware/uploadMiddleware.js`.
- Project patterns: `server/controllers/projectController.js`, `server/services/projectService.js`, `server/routes/recruiterProjectRoutes.js`.
- Frontend service pattern: `client/src/services/http.service.js`.
- Frontend UI patterns: `client/src/pages/Portfolio.jsx`, `client/src/components/common/StatCard.jsx`, `ProjectCard`, `ProjectForm`, `ProjectScoreCard`, `TechnologyBadge`.
- AI scoring pattern: `ai-engine/app/routers/project_scoring.py`, `ai-engine/services/project_scoring.py`, `ai-engine/schemas/project_schema.py`.
- Unified candidate score: `ai-engine/services/coding_scoring.py` and `/unified-score`.

## API Flow
- Candidate CRUD uses `/api/certificates`.
- Candidate stats use `/api/certificates/stats`.
- Candidate evidence upload uses multipart form data on create/update.
- Candidate scoring uses `/api/certificates/:id/score`.
- Candidate verification workflow uses `/api/certificates/:id/verify`.
- Recruiter certificate retrieval uses `/api/certificates/candidate/:candidateId`.

## Database Flow
- One user has many certificates via `Certificate.userId`.
- Certificate metadata is stored in MongoDB.
- Evidence is stored as a file reference and metadata, not embedded binary.
- Useful indexes cover candidate, issuer, category, verification status, and duplicate lookup.

## AI Scoring Flow
- Express sends certificate metadata to FastAPI `/certificate-score`.
- FastAPI delegates scoring to `services/certificate_scoring.py`.
- Score is certificate relevance and evidence contribution, not authenticity detection.
- Unified score now accepts optional `certificateScore` and includes it as an 8% factor.

## Risks
- Legacy inline `/api/portfolio/certificates` endpoints remain in `portfolioRoutes.js`; frontend service now points to `/api/certificates`.
- Upload storage is local disk; production deployments need persistent object storage.
- Verification is workflow-based and evidence-aware, but does not perform issuer verification.
- Existing dashboards expose only candidate certificate stats; deeper recruiter analytics can be expanded later.
