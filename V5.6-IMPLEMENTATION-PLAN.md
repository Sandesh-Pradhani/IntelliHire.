# IntelliHire V5.6 — Unified Candidate Intelligence Dashboard Implementation Plan

## 1. Executive Summary

IntelliHire V5.6 is an integration and recruiter user experience milestone. It consolidates multiple candidate signals (Resume, NLP Skill Extraction, Coding Profiles, Academic Profile, Project Portfolio, Certificates, and AI Evaluation) into one unified, explainable recruiter-facing Candidate Intelligence experience.

---

## 2. Current Architecture (V5.5 Audit)

### 2.1 Backend (Node.js / Express + MongoDB)
- **Domain Models**:
  - `User`: Identity, email, role (`candidate` / `recruiter`)
  - `Resume`: Uploaded resumes, ATS score, extracted skills, version history
  - `AcademicProfile`: CGPA, branch, college, graduation year, current semester, backlogs
  - `CodingProfile`: Unified GitHub, LeetCode, HackerRank usernames & activity metrics
  - `Project`: Titles, descriptions, technologies, GitHub URLs, Live Demo URLs, embedded `projectScore`
  - `Certificate`: Certification names, issuers, issue/expiry dates, credential URLs
  - `Application`: Candidate ID, Job ID, pipeline statuses (`Applied`, `Screening`, `Shortlisted`, `Interview`, `Selected`, `Rejected`, `Hired`), ATS score, match score, timeline history, recruiter notes
  - `Job`: Title, company, description, technologies, requirements, location, job type
- **Services**:
  - `resumeBuilderService.js`: Profile data aggregation
  - `candidateTwinService.js`: Digital twin & knowledge graph generation
  - `aiService.js`: FastAPI AI engine proxy
  - `projectService.js`: Portfolio management
  - `codingProfileController.js` / services: GitHub, LeetCode, HackerRank sync

### 2.2 AI Engine (FastAPI Microservice)
- Routers: `matching.py`, `ranking.py`, `insights.py`, `resume.py`, `coding_profile.py`, `project_scoring.py`, `resume_builder.py`
- NLP skill extractor using spaCy
- TF-IDF and SBERT semantic vector similarity calculation
- Rule-based & weighted ranking algorithms

### 2.3 Frontend (React 19 / Vite / Tailwind CSS)
- Pure client-side React with custom design system, Inter typography, Lucide React icons
- Role-based routing (`CandidateRoutes`, `RecruiterRoutes`, `ProtectedRoute`)
- Unified HTTP service (`http.service.js`) with auth headers & error handling

## 3. Data Sources & Schema Integration

| Domain Signal | Model | Primary Key | Key Fields |
|---|---|---|---|
| Identity | `User` | `_id` | `name`, `email`, `role`, `createdAt` |
| Resume | `Resume` | `userId` | `fileName`, `atsScore`, `extractedSkills`, `uploadedAt` |
| Academic | `AcademicProfile` | `candidateId` | `cgpa`, `branch`, `college`, `graduationYear`, `backlogs` |
| Coding | `CodingProfile` | `candidateId` | `githubUsername`, `leetcodeUsername`, `hackerrankUsername`, platform activity subdocuments |
| Projects | `Project` | `userId` | `title`, `description`, `technologies`, `githubUrl`, `liveDemoUrl`, `projectScore` |
| Certificates | `Certificate` | `userId` | `name`, `issuer`, `credentialUrl`, `credentialId` |
| Applications | `Application` | `candidateId` + `jobId` | `jobTitle`, `status`, `atsScore`, `matchScore`, `timeline`, `recruiterNotes` |

## 4. API Endpoints

### Express Backend Endpoints

| Method | Endpoint | Purpose | Access |
|---|---|---|---|
| `GET` | `/api/candidates/:candidateId/intelligence` | Load unified candidate intelligence (optional `?jobId=`) | Recruiter / Candidate (Self) |
| `GET` | `/api/candidates/me/intelligence` | Candidate self intelligence view | Candidate |
| `POST` | `/api/candidates/:candidateId/action` | Recruiter hiring actions (`Shortlist`, `Interview`, `Reject`, `Hire`) | Recruiter |
| `GET` | `/api/intelligence/candidate/:candidateId` | Backward-compatible candidate intelligence route | Recruiter / Candidate (Self) |
| `GET` | `/api/intelligence/me` | Backward-compatible candidate self route | Candidate |

## 5. Candidate Data Flow & Scoring Consolidation

```
   Recruiter requests candidate intelligence:
   GET /api/candidates/:candidateId/intelligence?jobId=...
                      │
                      ▼
       candidateIntelligenceController
                      │
                      ▼
       candidateIntelligenceService
                      │
   ┌──────────────────┴───────────────────────────────────────────────────────┐
   │ Parallel MongoDB Queries (Promise.all):                                  │
   │ 1. User.findById(candidateId)                                            │
   │ 2. Resume.find({ userId: candidateId })                                  │
   │ 3. AcademicProfile.findOne({ candidateId })                              │
   │ 4. CodingProfile.findOne({ candidateId })                                │
   │ 5. Project.find({ userId: candidateId })                                 │
   │ 6. Certificate.find({ userId: candidateId })                            │
   │ 7. Application.find({ candidateId }).populate('jobId')                  │
   │ 8. Job.findById(jobId) [if jobId provided]                               │
   └──────────────────┬───────────────────────────────────────────────────────┘
                      │
                      ▼
   ┌──────────────────────────────────────────────────────────────────────────┐
   │ AI Scoring & Consolidation (One Source of Truth):                        │
   │ - ATS Score (0-100): From active resume atsScore                         │
   │ - Semantic Match (0-100): AI Engine /job-match against target job        │
   │ - Academic Score (0-100): Calculated from CGPA & backlogs                │
   │ - Coding Score (0-100): Problems solved across LeetCode/GitHub/HackerRank│
   │ - Project Score (0-100): Quality, tech breadth, code & demo links        │
   │ - Certificate Score (0-100): Validated certifications on record          │
   │ - Final AI Composite Score: Weighted multi-factor consolidation          │
   │ - AI-Assisted Recommendation Tier: Explainable thresholds                │
   │ - Deterministic Strengths & Skill Gap Identification                     │
   └──────────────────┬───────────────────────────────────────────────────────┘
                      │
                      ▼
   Unified JSON response delivered to frontend CandidateIntelligence page
```

## 7. Risks & Mitigation Strategy

| Risk | Impact | Mitigation Strategy |
|---|---|---|
| AI Engine offline during job matching | High | Deterministic keyword and skill-overlap fallback logic ensures scores and skill gaps are always computed without 500 errors. |
| Missing candidate data (no coding profile, projects, or certificates) | Medium | Resilient service structure; missing fields return empty arrays/zeros instead of undefined/null; UI renders clear empty states. |
| N+1 database queries | High | All domain queries are fetched in parallel with `Promise.all` in a single round-trip. |
| Authorization breaches | High | Express controller enforces strict role-based access: recruiters access any candidate; candidates can only query their own ID. |
| UI breakage / styling inconsistencies | Medium | Strict adherence to existing Tailwind tokens, Inter font, card styling, and component patterns. |
