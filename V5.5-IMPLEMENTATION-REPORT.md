# V5.5 Implementation Report — AI Resume Builder & Optimizer

## Objective

Add an AI-powered Resume Builder and Optimizer to IntelliHire that allows candidates to build ATS-friendly resumes from their existing profile data. The system reuses structured candidate information across all IntelliHire collections and provides AI-powered optimization, ATS analysis, and PDF export.

## Architecture

```
Candidate Profile Data (8 MongoDB collections)
    ↓
ResumeBuilder Service (aggregation + transformation)
    ↓
ResumeBuilder Document (normalized resume data)
    ↓
AI Engine (summary generation, optimization, ATS analysis)
    ↓
Frontend (two-panel editor + live preview)
    ↓
PDF Export (server-side pdfmake)
```

## Resume Data Flow

```
1. Candidate opens Resume Builder
   → GET /api/resume-builder
   → resumeBuilderService.getOrCreate(userId)
   → If no ResumeBuilder doc exists:
     → resumeBuilderService.aggregateProfile(userId)
     → Queries: User, Resume, Project, Certificate, CodingProfile,
                Experience, Language, PortfolioLink, AcademicProfile
     → Transforms into resume-ready format
     → Creates ResumeBuilder document
   → Returns structured resume data

2. Candidate edits sections
   → Frontend state updates (React useState)
   → Live preview re-renders in real-time

3. Candidate saves
   → PUT /api/resume-builder
   → resumeBuilderService.save(userId, data)
   → Updates ResumeBuilder document

4. Candidate generates summary
   → POST /api/resume-builder/generate-summary
   → Express proxies to FastAPI
   → resume_optimizer.generate_summary()
   → Returns professional summary (factually grounded)

5. Candidate runs ATS analysis
   → POST /api/resume-builder/ats-analyze
   → Express proxies to FastAPI
   → resume_optimizer.analyze_ats()
   → Returns score, coverage, recommendations

6. Candidate exports PDF
   → POST /api/resume-builder/export-pdf
   → pdfGeneratorService.generatePdf(data)
   → Returns PDF buffer with text-based content
```

## AI Optimization Flow

The AI engine follows strict safety rules:

1. **Summary Generation**: Uses skills, projects, experience, education, and certificates to generate a 2-4 sentence professional summary. Never invents achievements.

2. **Section Optimization**: Only rephrases existing content using action verbs and improved structure. Never adds new information.

3. **ATS Analysis**: Analyzes resume text for keyword coverage, section completeness, format compatibility, and job-description alignment.

4. **Job Matching**: Compares resume keywords against job description. Recommends adding missing keywords IF relevant — never auto-inserts.

## ATS Flow

The ATS analysis evaluates:
- **Skill relevance** (keyword density and coverage)
- **Section completeness** (personalInfo, summary, skills, education, experience, projects, certificates)
- **Format compatibility** (word count, structure)
- **Job-description alignment** (when job description provided)

Returns:
- `atsScore` (0-100)
- `keywordCoverage` (percentage)
- `matchedKeywords[]`
- `missingKeywords[]`
- `sectionCompleteness{}`
- `recommendations[]`

## PDF Generation

- **Library**: pdfmake (pure JavaScript, no headless browser)
- **Output**: Text-based PDF with selectable text (ATS-friendly)
- **Page**: A4 with clean margins (40px)
- **Typography**: Roboto font family
- **Structure**: Clear section headings with blue underline
- **Footer**: Page numbers

## Security

- All endpoints require JWT authentication via `authMiddleware`
- All endpoints require `candidate` role via `requireRole('candidate')`
- Resume data is scoped to `userId` — candidates can only access their own resume
- Version restore operations validate ownership
- AI engine does not have direct database access — all data flows through Express

## Known Limitations

1. **PDF templates**: Only one template (Classic ATS) — additional templates planned for V6
2. **Version limit**: Maximum 10 versions per candidate
3. **AI safety**: AI never fabricates data but may produce generic language for sparse profiles
4. **PDF fonts**: Limited to Roboto — custom fonts not yet supported
5. **Real-time collaboration**: Not supported — single-user editing only
